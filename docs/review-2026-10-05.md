# UB Circus — одоогийн хувилбарын нягт шалгалт

Огноо: 2026-10-05 · Local хэрэглээнд зориулсан хувилбар.

## Дүгнэлт

Үндсэн сайт, тоглолтын дэлгэрэнгүй хуудас, захиалга хадгалах API, admin эрх болон төлөв хадгалах урсгал ажиллаж байна. Гэхдээ засах **14 асуудал** байна: 1 өндөр ач холбогдолтой, 8 дунд, 5 бага. Доорх жагсаалт бодитоор давтан гаргасан асуудал болон кодоос тогтоосон нөхцөлүүдийг ялгаж тэмдэглэнэ.

Энэ удаад засвар оруулаагүй. Жинхэнэ admin бүртгэл, хүсэлт, контентыг өөрчлөөгүй. Туршилтын захиалга, admin бүртгэл, зураг болон эвдэрсэн файл нь тусгаарласан түр өгөгдөлд байсан.

## Өндөр ач холбогдолтой

### 1. Дахин илгээсэн өөрчлөгдсөн хүсэлт хуучин агуулгаараа үлддэг — P1

**Нотолгоо:** тусгаарласан store туршилтаар батлагдсан.

- Хүсэлт серверт хадгалагдсан боловч хэрэглэгчид хариу очихгүй/timeout болох нөхцөлд form нээлттэй үлдэнэ.
- Хэрэглэгч brief эсвэл огноо зэрэг мэдээллээ өөрчлөөд дахин илгээхэд `submissionId` хэвээр байна.
- Сервер ижил ID байвал payload-ийг харьцуулахгүйгээр хуучин receipt буцаадаг. Шинэ мэдээлэл хадгалагдахгүй ч амжилттай харагдана.
- Туршилтаар өөр brief явуулахад ижил receipt буцаж, анхны brief хадгалагдсан хэвээр байсан.

**Засвар:** submission ID-тай хамт анхны payload-ийн fingerprint хадгалж, өөр payload ирвэл 409 буцаах; client нь ижил retry болон шинэчилсэн хүсэлтийг ялгах. Алдаа гарсан бүрт зүгээр шинэ UUID өгөх нь хариу тасарсан хүсэлтийг давхардуулах тул хангалтгүй.

### 2. Контентын файл эвдэрвэл admin хүртэл нээгдэхгүй — P2

**Нотолгоо:** тусгаарласан production сангийн `content.json`-ийг буруу JSON болгоход `/` болон `/admin` хоёулаа HTTP 500 болсон; туршилтын дараа файлыг сэргээсэн.

**Засвар:** admin shell-ийг public content loader-ийн алдаанаас тусгаарлах; сүүлчийн зөв хувилбарын backup болон тодорхой recovery үйлдэл нэмэх. Алдаа гарвал default контентоор чимээгүй дарж бичиж болохгүй.

## Асуудлаас тусдаа дараагийн ажил

- Бодит зураг, нүүрний видео, бодит холбоо барих мэдээлэл болон хуваарь нийлүүлэх. Одоогийн контентын бизнесийн үнэн зөвийг энэ аудит батлахгүй.

- Нэг regression suite болгож өнөөдрийн туршилтуудыг хадгалан, дараагийн өөрчлөлт бүрийн дараа ажиллуулах.
